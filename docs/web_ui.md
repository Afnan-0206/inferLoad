# InferLoad Web UI — Local Interactive Benchmark Console

InferLoad includes a local browser interface for configuring, running, monitoring, and inspecting LLM inference benchmarks and SLO capacity reports.

The Web UI is an ergonomic client layer over the canonical InferLoad Python engine:
```text
Browser UI (Vanilla JS / CSS)
   │
   ▼ HTTP / JSON
InferLoad Web API (FastAPI / Uvicorn)
   │
   ▼ Direct Python Function Calls
Canonical Engine (ExperimentRunner, WorkloadGenerator, CapacityAnalysis)
   │
   ▼ File System Artifacts
results/<experiment-id>/
   ├── summary.json
   ├── points.csv
   ├── report.md
   └── plots/
```

---

## 1. Quick Start

### Start Web Server
```bash
inferload web
```
Optional host and port flags:
```bash
inferload web --host 127.0.0.1 --port 8000
```

Once started, the console outputs:
```text
InferLoad Web UI
Running at: http://127.0.0.1:8000
Press Ctrl+C to stop.
```

Navigate to `http://127.0.0.1:8000` in your web browser.

## 2. Architecture & Design Principles

1. **Existing Engine is the Single Source of Truth:**
   - The Web UI does not reimplement or duplicate workload generation, metric collection, percentile calculations, or SLO compliance logic.
   - Experiments initiated from the browser are dispatched via `inferload.experiment.ExperimentRunner.run_experiment()`.
   - Results, charts, and Markdown reports are generated by the exact same classes used by the CLI.

2. **Zero Fabricated or Mock Results:**
   - The UI displays an empty initial state until an experiment is run or a historical experiment is loaded from the filesystem.
   - All latency numbers, token counts, throughput metrics, and server telemetry come exclusively from real measurements.

3. **High Information Density & Technical Styling:**
   - Engineered as a performance testing workstation / observability console.
   - Uses strict technical styling: clean dark theme, explicit units (`ms`, `req/s`, `%`), clear status indicators, and responsive tables.
   - Adheres strictly to the mandatory terminology: **"Highest Observed Compliant Tested Concurrency"** (avoiding unscientific terms like "Maximum Capacity").

4. **Non-Blocking Execution Model:**
   - Experiment execution is dispatched as an asynchronous background worker.
   - The browser polls status every 750ms, rendering real-time execution progress:
     - Active trial number / total trials
     - Current concurrency level and repetition
     - Elapsed wall-clock time
   - If a benchmark fails (e.g. invalid endpoint or connection error), an informative error banner is displayed with the exact exception details.

5. **Local Only & Path Safe:**
   - Runs locally on loopback (`127.0.0.1`).
   - No external cloud services, third-party CDNs, external analytics, or remote telemetry.
   - Strict path traversal guards (`target.is_relative_to(base_dir)`) prevent unauthorized file access.

## 3. Web API Specification

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| `GET` | `/` | Serves main single-page application (`index.html`). |
| `GET` | `/api/health` | Host environment metadata (OS, CPU cores, RAM, GPU/CUDA status) and local Ollama model auto-discovery. |
| `POST` | `/api/validate` | Pre-flight validation of benchmark form configuration against Pydantic models. |
| `POST` | `/api/experiments` | Validates configuration and initiates background benchmark run; returns `job_id`. |
| `GET` | `/api/experiments/{job_id}` | Returns current job status, execution progress (`trials_completed`, `total_trials`, `current_trial`), and result summary upon completion. |
| `GET` | `/api/experiments/{job_id}/report` | Returns generated Markdown report content. |
| `GET` | `/api/experiments/{job_id}/artifacts/{path}` | Downloads specific experiment artifacts (`summary.json`, `points.csv`, plots). Path traversal protected. |
| `GET` | `/api/history` | Scans `results/` directory and returns metadata summaries of historical benchmark runs. |
| `GET` | `/api/history/{dir_name}` | Loads an existing experiment run directly into the dashboard. |

## 4. UI Capabilities Walkthrough

### Target & Model Discovery
- **Target Endpoint:** Default is `http://127.0.0.1:11434/v1` (Ollama) or `http://127.0.0.1:8000/v1` (vLLM).
- **Auto-Discovery:** Automatically queries local Ollama tags on page load and renders clickable model chips (e.g., `qwen2.5:0.5b`, `qwen2.5:7b`).

### Workload Configuration
- **Concurrency Sweep:** Comma-separated list of concurrency levels (e.g., `1, 2, 4`).
- **Repetitions & Warmup:** Configure independent repetitions per sweep point and warmup requests to isolate socket/cache priming.
- **Dynamic Prompts:** Add or remove custom prompt strings passed directly to the workload generator without hidden defaults.
- **Generation Parameters:** `max_tokens`, `temperature`, `seed`, and streaming toggle (`ON`/`OFF`).

### SLO & Capacity Criteria
- **TTFT p95 Maximum (ms):** Ceiling for time to first token.
- **Total Latency p95 Maximum (ms):** Ceiling for end-to-end response completion.
- **Error Rate Maximum (%):** Maximum acceptable failure percentage.
- **Throughput Minimum (req/s):** Floor for request throughput.

### Results Presentation
- **Hero Metric:** Displays **Highest Observed Compliant Tested Concurrency**.
- **Results Table:** Concurrency, completed trials, requests per trial, TTFT (p50, p95, p99), Latency (p50, p95, p99), Throughput (req/s), Output tokens/s, Error rate %, and SLO compliance status.
- **SLO Analysis Table:** Details tested points against configured criteria with explicit violation reasons.
- **Saturation Observations:** Surfaces empirical inflection observations (e.g., latency surges vs. throughput plateaus) without inventing causal claims.
- **Visual Performance Curves:** Embedded charts for Concurrency vs. TTFT p95, Total Latency p95, Throughput, and Error Rate.
- **Full Report:** Live rendered Markdown report directly in-browser.
- **Raw Evidence Inspection:** Expandable JSON viewer for raw record-level inspection.
- **Artifact Downloads:** One-click downloads for `summary.json`, `points.csv`, `report.md`, and PNG plots.
- **History Drawer:** Inspect and load any prior experiment run without losing previous data.
